не программист. Делай по порядку, ничего не пропускай. Команды нужно **копировать
целиком** и вставлять в терминал сервера.

> 💡 Если что-то не получается — не паникуй. В конце есть раздел «Если что-то
> пошло не так». А ещё всегда можно скинуть скриншот ошибки тому, кто дал тебе бота.

## 1. Что умеет этот бот

Бот сам обрабатывает заказы на FunPay и выдаёт покупателям доступы. Управляешь
ты всем через **Telegram-админку** (отдельный бот в телеге).

**Главное:**
- 🎮 **Аренда Steam-аккаунтов.** Покупатель оплатил → бот сам выдал логин/пароль,
  присылает Steam Guard коды по запросу, а когда время вышло — выкидывает сессии
  и возвращает аккаунт в пул.
- 🟣 **Аренда Chat (ChatGPT) аккаунтов.** Несколько покупателей сидят на одном
  аккаунте (по «слотам»), бот выдаёт код входа (2FA) по команде.
- ⏱ **Продление аренды** — отдельным лотом покупатель докупает время.
- 🔄 **Автоподнятие лотов** на FunPay, чтобы они были выше в списке.
- 🔔 **Уведомления** тебе в Telegram: новые заказы, проблемы, истечения.
- 📊 **Дашборд и статистика** прямо в телеге: сколько аккаунтов свободно, сколько
  в аренде, активные аренды (Steam и Chat отдельно), выручка.
- 🗄 **Автобэкапы базы данных** (чтобы не потерять аккаунты и заказы).

> ⚠️ Бот работает только с **обычными лотами аренды**, которые ты настроишь.
> Лоты с автовыдачей FunPay бот не трогает — их выдаёт сам FunPay.

## 2. Что нужно подготовить заранее

Собери это до начала — без этого бот не заведётся:

| Что | Где взять |
|---|---|
| **Сервер** (VPS) на Ubuntu | Шаг 1 ниже |
| **golden_key** аккаунта FunPay | из cookies браузера (см. Шаг 6) |
| **User-Agent** браузера | сайт `whatismybrowser.com/detect/what-is-my-user-agent` |
| **Токен Telegram-бота** | у [@BotFather](https://t.me/BotFather) в телеге |
| **Свой Telegram ID** (число) | у [@userinfobot](https://t.me/userinfobot) |
| **Доступ к репозиторию** на GitHub | у того, кто дал тебе бота (Шаг 3) |
| **(возможно) Прокси** | если сервер за границей — см. Шаг 6 |

## Шаг 1. Арендуем сервер

Бот живёт на «сервере» — это удалённый компьютер, который работает 24/7.

1. Зарегистрируйся у любого хостинга VPS (например **Timeweb Cloud**, **Aeza**,
   **Hetzner**, **VDSina** — любой, где есть Ubuntu).
2. Создай сервер с такими параметрами (минимум хватает):
   - ОС: **Ubuntu 24.04** (или 22.04)
   - 1 ядро CPU, **1 ГБ RAM**, 10 ГБ диска.
3. Выбор локации:
   - **Сервер в России** — проще, прокси скорее всего не нужен.
   - **Сервер за границей** — дешевле/стабильнее, но **обязательно нужен прокси**
     (иначе Steam может заблокировать аккаунты за вход из чужой страны). См. Шаг 6.
4. После создания хостинг пришлёт тебе: **IP-адрес сервера**, **логин** (обычно
   `root`) и **пароль**. Сохрани их.

---

## Шаг 2. Подключаемся к серверу

Тебе нужен «терминал», чтобы вводить команды на сервере.

- **Windows:** скачай и открой бесплатную программу **PuTTY** (или используй
  встроенный PowerShell). В PuTTY впиши IP сервера → Open → введи логин `root` и
  пароль.
- **Mac / Linux:** открой приложение **Терминал** и введи (подставь свой IP):
  ```bash
  ssh root@ВАШ_IP_СЕРВЕРА
  ```
  Введи пароль (он не отображается при вводе — это нормально, просто печатай и жми Enter).

Если увидел приглашение вида `root@server:~#` — ты внутри сервера. 🎉
**Все команды ниже вводим здесь, на сервере.**

---

## Шаг 3. Создаём SSH-ключ для GitHub

Код бота лежит в **закрытом** репозитории на GitHub. Чтобы сервер мог его скачать,
ему нужен «ключ-пропуск».

**3.1. На сервере создай ключ** (просто скопируй команду, на все вопросы жми Enter):
```bash
ssh-keygen -t ed25519 -C "funpay-bot-server" -f ~/.ssh/id_ed25519 -N ""
```

**3.2. Покажи публичную часть ключа:**
```bash
cat ~/.ssh/id_ed25519.pub
```
Скопируй **всю строку**, которая начинается на `ssh-ed25519 ...` (это публичный
ключ, его можно показывать — он не секретный).

**3.3. Добавь ключ на GitHub.** Есть два варианта — выбери один:

**Вариант А (рекомендуется) — попроси владельца репозитория добавить ключ.**
Отправь ему скопированную строку и попроси:
> «Добавь этот ключ в репозиторий: Settings → Deploy keys → Add deploy key,
> вставь строку, галку *Allow write access* НЕ ставь».

Это самый безопасный вариант: ключ даёт доступ только к этому одному репозиторию,
только на чтение.

**Вариант Б — если у тебя есть свой аккаунт GitHub с доступом к репозиторию.**
Зайди на github.com → нажми на аватарку → **Settings** → **SSH and GPG keys** →
**New SSH key** → вставь строку → **Add SSH key**.

**3.4. Проверь, что доступ работает:**
```bash
ssh -T git@github.com
```
Если спросит «Are you sure you want to continue connecting?» — впиши `yes` и Enter.
Должно появиться сообщение со словами `successfully authenticated`. Значит всё ок.

## Шаг 4. Скачиваем код бота

```bash
git clone git@github.com:malodyschev/funpay_bot.git
cd funpay_bot
```

> Если у тебя другой адрес репозитория — владелец даст правильную ссылку

Теперь ты внутри папки с ботом. Проверь командой `ls` — должны быть файлы вроде
`docker-compose.yml`, `Dockerfile`, `.env.example`.

## Шаг 5. Ставим Docker

Docker — это программа, которая запускает бота в «коробке», чтобы не возиться с
зависимостями. Установи её и небольшую страховку от нехватки памяти:

```bash
# Установка Docker (одной командой)
curl -fsSL https://get.docker.com | sh

# Файл подкачки 1 ГБ — страховка от вылетов на сервере с 1 ГБ памяти
sudo fallocate -l 1G /swapfile && sudo chmod 600 /swapfile
sudo mkswap /swapfile && sudo swapon /swapfile
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
```

Проверь, что Docker встал:
```bash
docker --version
```
Если показал версию — отлично.

## Шаг 6. Заполняем настройки (.env)

Это самый важный шаг. Файл `.env` — это «паспорт» бота со всеми ключами.

**6.1. Создай файл настроек из шаблона и папку для логов:**
```bash
cp .env.example .env
mkdir -p logs
```

**6.2. Сгенерируй ключ шифрования** (им шифруются пароли аккаунтов в базе):
```bash
docker run --rm python:3.12-slim sh -c "pip -q install cryptography && python -c 'from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())'"
```
Скопируй полученную строку — вставишь её ниже в `encryption_key`.

> 🔴 **ОЧЕНЬ ВАЖНО.** Этот ключ нельзя менять и нельзя терять. Им зашифрованы все
> пароли Steam/Chat в базе. Поменяешь — все сохранённые аккаунты «сломаются».
> Сохрани его отдельно (в заметках/менеджере паролей).

**6.3. Открой файл настроек для редактирования:**
```bash
nano .env
```
Откроется простой редактор. Двигайся стрелками, впиши значения после знака `=`
(без пробелов и без кавычек). Что куда вписать:

| Параметр | Что вписать / где взять |
|---|---|
| `funpay_golden_key` | Зайди на funpay.com в браузере → F12 → вкладка **Application** (или «Хранилище») → **Cookies** → найди `golden_key` → скопируй значение |
| `funpay_user_agent` | Открой `whatismybrowser.com/detect/what-is-my-user-agent` тем же браузером и скопируй строку User-Agent |
| `bot_token` | Напиши [@BotFather](https://t.me/BotFather) → `/newbot` → задай имя → он пришлёт токен вида `1234:AAAA...` |
| `admin_id` | Напиши [@userinfobot](https://t.me/userinfobot) — он пришлёт твой числовой ID. Если админов несколько — впиши их в `admin_ids` через запятую |
| `secret_phrase` | Придумай любую секретную фразу (нужна для входа в админку) |
| `encryption_key` | Вставь строку, которую сгенерировал в шаге 6.2 |
| `db_password` | Придумай любой пароль для базы данных (например `MyStrongPass123`) |
| `log_file` | Впиши `logs/bot.log` |
| `log_is_json` | Впиши `true` |
| `proxy_url` | **Только если сервер за границей** — впиши свой прокси (формат `http://user:pass@host:port` или `socks5://user:pass@host:port`). Если сервер в России — оставь пустым |

> 💡 **Про прокси.** Если твой сервер в России и Steam/FunPay с него открываются —
> прокси можно не указывать. Если сервер за рубежом — прокси **обязателен**, иначе
> рискуешь блокировкой Steam-аккаунтов. Прокси покупается отдельно (резидентный/
> мобильный РФ). Если FunPay-прокси не пускает Steam (ошибка 502) — можно указать
> отдельный прокси для Steam в `steam_proxy_url`.

**6.4. Сохрани файл:** нажми `Ctrl+O`, затем `Enter`, потом `Ctrl+X` для выхода.

## Шаг 7. Запускаем бота

```bash
docker compose up -d --build
```
Первый запуск занимает несколько минут (скачиваются и собираются компоненты).

Посмотри, что бот ожил:
```bash
docker compose logs -f bot
```
В логах должны появиться строки вроде:
- `funpay authorized as <твой ник>` — FunPay подключился ✅
- `funpay listener started` — слушает новые заказы ✅
- `admin bot started` — Telegram-админка работает ✅

База данных создаётся автоматически при старте — ничего вручную делать не надо.

Чтобы выйти из просмотра логов — нажми `Ctrl+C` (бот при этом продолжит работать).

> ❌ Если видишь `Авторизация FunPay не удалась` — скорее всего протух `golden_key`
> или мешает IP сервера (нужен прокси). Обнови значения в `.env` и перезапусти
> (см. раздел «Обслуживание»).

## Шаг 8. Первичная настройка в Telegram

1. Открой в Telegram своего бота (того, чей токен ты получил у @BotFather) и нажми
   **/start**. Появится меню админки.
2. Зайди в **🗂 Лоты и аккаунты**. Твои лоты с FunPay подтянутся автоматически как
   **черновики** (неразобранные). Их нужно настроить:
   - Открой лот → задай **категорию** (Steam или Chat), **длительность аренды**,
     добавь **аккаунты** в пул, затем **включи** лот.
3. Добавление аккаунтов:
   - **Steam:** проще всего через кнопку «🔑 Привязать (логин+пароль)» или загрузить
     `maFile` (см. ниже в «Обслуживании»).
   - **Chat:** кнопка «➕ Добавить Chat-аккаунт» — вводишь логин, пароль и 2FA-ключ,
     задаёшь число слотов (сколько человек одновременно).
4. **⏱ Лот продления** (если нужен): создаётся как отдельный лот, добавляет время к
   активной аренде покупателя.

Полезное в меню:
- **📊 Дашборд** — сколько аккаунтов свободно/в аренде, состояние Chat-пулов.
- **📋 Активные аренды** — кто сейчас арендует (отдельно Steam и Chat).
- **📈 Статистика** — заказы за периоды и примерная выручка.

## Как покупатели пользуются ботом

Это команды, которые **покупатель** пишет тебе в чат заказа на FunPay (бот отвечает
сам). Можешь добавить их в описание лота:

| Команда | Что делает |
|---|---|
| `!acc` (или `!акк`, `!креды`) | получить логин/пароль арендованного аккаунта |
| `!код` (или `!code`) | получить текущий Steam Guard код |
| `!время` (или `!time`) | сколько осталось времени аренды |
| `!chat-code` | получить код входа (2FA) для Chat-аккаунта |
| `!chat-acc` | получить данные Chat-аккаунта |
| `!продлить` | как продлить аренду |
| `!admin` | позвать живого продавца (придёт уведомление тебе) |
| `!help` | список команд для покупателя |

## Обслуживание

Все команды выполняются на сервере, **внутри папки бота** (`cd funpay_bot`).

**Перезапустить бота:**
```bash
docker compose restart bot
```

**Остановить / снова запустить:**
```bash
docker compose down       # остановить всё
docker compose up -d       # запустить снова
```

**Обновить бота** (когда вышли изменения в коде):
```bash
git pull && docker compose up -d --build
```

**Посмотреть логи:**
```bash
docker compose logs -f bot
```
(выход из просмотра — `Ctrl+C`)

**Сделать бэкап базы прямо сейчас** (или просто напиши боту в телеге `/backup`):
```bash
docker compose exec postgres pg_dump -U postgres funpay_bot > backup_$(date +%F).sql
```

**Загрузить Steam-аккаунт из maFile:**
```bash
# 1) загрузи файл .maFile на сервер (через PuTTY/WinSCP или scp), затем:
docker compose cp ./acc.maFile bot:/tmp/acc.maFile
docker compose exec bot python __main__.py load-account --mafile /tmp/acc.maFile --lot-id <НОМЕР_ЛОТА>
```
(номер лота виден в админке; команда спросит пароль от Steam)

> ℹ️ После перезагрузки сервера бот и база поднимаются сами (стоит автозапуск).

## Если что-то пошло не так

**Бот не стартует / падает сразу.** Посмотри логи: `docker compose logs --tail=50 bot`.
В конце обычно написана причина.

**`Авторизация FunPay не удалась`.** Протух `golden_key` (зайди в браузер, скопируй
свежий) или мешает IP сервера → нужен прокси. Поправь `.env` и перезапусти
(`nano .env`, затем `docker compose up -d --build`).

**`нужны BOT_TOKEN и ADMIN_ID`.** Не заполнены `bot_token` и/или `admin_id` в `.env`.

**Telegram-бот не отвечает на /start.** Проверь, что `bot_token` верный и что ты
пишешь именно своему боту. Твой `admin_id` должен быть указан в `.env` — иначе бот
тебя «не узнаёт».

**Steam-аккаунты банятся/флагаются.** Почти всегда — вход из чужой страны без
прокси. Поставь резидентный РФ-прокси в `proxy_url` (и при необходимости
`steam_proxy_url`).

**Изменил `.env` — изменения не подхватились.** После правки `.env` всегда
перезапускай: `docker compose up -d` (или `--build`, если меняли код).

**Не уверен — спроси.** Скинь скриншот ошибки из логов тому, кто дал тебе бота.

Удачи! После настройки бот работает сам — тебе остаётся только следить за пулом
аккаунтов и отвечать на `!admin`. 🚀
